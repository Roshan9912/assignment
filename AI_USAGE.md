# AI Usage and Verification

## Tools used

- GitHub Copilot in VS Code was used to assist with project scaffolding, source-specific scraper code, test generation, documentation, and review of the pipeline integration.
- The local Python environment and pytest were used as the final verification tools; no external API keys or generated data were used.

## Representative prompts

1. “Create a Python ETL pipeline for Books to Scrape and Quotes to Scrape with dynamic pagination, shared schema, cleaning, validation, deduplication, logging, and output files.”
2. “Implement resilient Requests sessions with retry handling and 0.5-second request pacing.”
3. “Write pure functions for text, price, rating, tags, and URL normalization and add unit tests.”
4. “Implement SHA-256 duplicate fingerprints using source, title/author, and quote-text rules.”
5. “Create a summary report that reconciles scraped, cleaned, rejected, duplicate, and final record counts.”

## AI-assisted areas

- The shared HTTP helper and retry configuration.
- Source-specific extraction functions for books and quotes.
- Common schema transformation and cleaning functions.
- Validation reason reporting.
- Fingerprint construction and duplicate separation.
- Main pipeline orchestration and output writing.
- README and AI_USAGE documentation.

## Changes after reviewing generated output

- Replaced a simplistic basic-config setup with explicit directory creation and logging to both console and the log file.
- Made validation run once per cleaned record and stored its result before deduplication.
- Added rejected reason counts and a summary reconciliation field.
- Used source-specific identity rules for books and quotes exactly as documented.
- Added live source checks and confirmed that each scraper follows its actual next links.
- Set a robust 15-second request timeout and request pacing in the shared helper.

## Incorrect or incomplete suggestions found

- Some generated examples treated the two site schemas as if they had identical fields and suggested fabricated values for missing fields; the implementation instead uses empty CSV cells.
- A raw HTML string check for pagination was not sufficient because BeautifulSoup parses the link correctly; verification used parsed selectors instead.
- The initial orchestration could have validated the same record twice and could have counted a rejected record differently from the reason breakdown. The final implementation validates once and derives the rejected total from the reason counts.
- The assignment expected roughly 1,100 rows, but the live public sites returned exactly 1,000 books and 100 quotes during verification; the pipeline preserves those real counts rather than forcing expected totals.

## Final verification

- Existing unit tests: 7 passed.
- Live HTTP check: both sites returned status 200.
- Live scraper check: 1,000 book records and 100 quote records were extracted through dynamic pagination.
- Full pipeline run: the command `python main.py` was executed after implementation.
- Output verification: the CSV was checked for matching columns, both source names, valid numeric prices, valid ratings, and the final row count matching the summary.
- The output files are generated by the current run and are included in the project workspace.
